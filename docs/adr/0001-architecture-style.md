# 1. Архітектурний стиль: Модульний моноліт

* **Статус:** Прийнято
* **Дата:** 2026-10-21

## Контекст
Проєкт "Task Tracker" розробляється одним розробником (соло-проєкт). Система наразі невелика і складається з базового CRUD для завдань. Потрібно обрати архітектурний стиль для подальшого розвитку: моноліт чи мікросервіси.

## Рішення
Я обрав стиль **Модульний моноліт**. 

## Альтернативи
* **Мікросервіси:** Відхилено. Це створить непотрібне навантаження на інфраструктуру, деплоймент та комунікацію (через мережу). Для поточного розміру команди та проєкту мікросервіси є надмірними (overengineering).

## Наслідки
* **Позитивні:** Легкий старт, просте тестування, єдина кодова база, прямі виклики функцій у пам'яті.
* **Негативні:** При сильному розростанні коду доведеться уважніше слідкувати за модульністю, щоб моноліт не перетворився на "велику грудку бруду" (Big Ball of Mud).

## Умови перегляду
Рішення може бути переглянуто, якщо команда розробників збільшиться до кількох незалежних команд, або якщо окрема частина застосунку (наприклад, відправка листів/сповіщень) вимагатиме принципово іншого масштабування.
