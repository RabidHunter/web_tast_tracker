# 3. Стиль API та формат помилок

* **Статус:** Прийнято
* **Дата:** 2026-10-21

## Контекст
Потрібен єдиний стандарт для проєктування API, щоб фронтенд міг передбачувано обробляти відповіді та помилки.

## Рішення
Я використовую стиль RESTful API.
* Ресурси іменуються у множині (наприклад, `/tasks`).
* Використовуються стандартні HTTP-методи (GET, POST, PUT/PATCH, DELETE).
* Статуси: 200 (OK), 201 (Created), 204 (No Content), 400 (Bad Request), 404 (Not Found).

### Єдиний формат помилки (ErrorResponse)
Усі помилки повинні повертатися у такому JSON-форматі:
```json
{
  "error": "Назва_Помилки",
  "code": "СТАНДАРТИЗОВАНИЙ_КОД",
  "details": [
    { "field": "поле", "message": "Опис помилки" }
  ]
}
